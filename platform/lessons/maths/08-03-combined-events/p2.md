## Why this matters

When two events have lots of possible outcomes, building a $52 \times 52$ grid is no fun. Tree diagrams handle those cases gracefully. They are the workhorse of every multi-step probability question on the paper.

A tree diagram lays out a multi-stage experiment as branching paths. Each stage of the experiment has its own set of branches; each branch carries a probability. To find the probability of a specific FULL PATH, you multiply the probabilities along its branches. To combine multiple paths into a single event (like "exactly one red"), you ADD the path probabilities.

This page focuses on **with replacement** experiments (also called **independent events**): the second stage does not know what happened on the first stage. Toss the same coin twice. Spin the same spinner twice. Draw a card from a deck, put it BACK, then draw again. Without replacement is the next page.

Tree-diagram questions are worth $3$ to $5$ marks each on the paper. The first marks come from drawing the tree with correct branch labels; the rest come from picking the right paths and doing the arithmetic.

Internalise these two. Almost every tree-diagram error is mixing them up.

## With replacement: branches stay equal

When you draw with replacement (or repeat an experiment that does not change anything), the second stage has the same probabilities as the first. The branch labels for "red" on stage 2 are the SAME as on stage 1, regardless of what happened on stage 1.

This is what the syllabus calls **independent events**: knowing the outcome of stage 1 gives you no information about stage 2.

Examples:
- Tossing a coin twice. Each toss is independent. $P(\text{heads on second}) = \tfrac{1}{2}$ regardless of the first.
- Rolling a die twice. $P(\text{six on second}) = \tfrac{1}{6}$ regardless of the first.
- Drawing from a bag WITH replacement: counters drawn are put back before the second draw, so probabilities reset.

The four endpoint probabilities for a two-stage two-outcome tree always sum to $1$. Useful as a quick check.

## Worked example: two independent tests

A student takes a driving test twice. Each time, the probability they pass is $0.65$, independent of the previous attempt. Find the probability that they pass **exactly one** of the two tests.

<iframe src="/widgets/probability-step-explorer.html?preset=p2-tree-with-replacement" style="width:100%;max-width:696px;height:560px;border:0;border-radius:10px;display:block;margin:18px auto" loading="lazy"></iframe>

**Step 1: Identify the paths.** There are TWO ways to pass exactly one:

- **PF**: pass on test 1, fail on test 2.
- **FP**: fail on test 1, pass on test 2.

(The other two cases, PP and FF, both have either zero or two passes.)

**Step 2: Probabilities on each branch.** $P(\text{pass}) = 0.65$ and $P(\text{fail}) = 1 - 0.65 = 0.35$. Since the tests are independent, these are the SAME on both stages.

**Step 3: Multiply along each path.**

$$P(\text{PF}) = 0.65 \times 0.35, \qquad P(\text{FP}) = 0.35 \times 0.65$$

Both products equal $0.2275$.

**Step 4: Add the two paths (the OR rule).**

$$P(\text{exactly one pass}) = P(\text{PF}) + P(\text{FP}) = 2 \times 0.65 \times 0.35 = 0.455$$

**Answer:** $P(\text{exactly one pass}) = \boxed{0.455}$. **[M1 for $2 \times 0.65 \times 0.35$; A1 for $0.455$ or $\tfrac{91}{200}$]**

Full marks $= 2$.

The factor of $2$ catches many students. It is there because the question asks for "exactly one", which can happen in $2$ orders (pass-then-fail or fail-then-pass). Each order has the same product, so you double once.

## The "factor of 2" rule

Whenever a question asks for "exactly one of two stages", and the two stages are independent, the answer has a factor of $2$ in it:

$$P(\text{exactly one}) = 2 \times P(\text{success}) \times P(\text{failure})$$

For independent events with three or more stages, the factor changes (e.g., "exactly one in three" gives a factor of $3$ because there are three orders). The rule is: factor equals the number of valid orders.

## When events are NOT independent

If the question says "without replacement", or if anything between stage 1 and stage 2 changes the situation, the events are NOT independent. Then the second-stage branch probabilities CHANGE depending on what happened first.

That is the next page. For now, all problems on this page assume the stages do not interact.

## Common mistakes

- **Adding instead of multiplying along a path.** $\tfrac{1}{2} + \tfrac{1}{2}$ is not $\tfrac{1}{4}$. Use $\times$ along a path; use $+$ to combine across paths.
- **Forgetting the factor of $2$** for "exactly one". A single multiplication gives only one of the two orders.
- **Assuming events are independent when the question says without replacement.** Re-read: if the second draw uses one fewer counter, the events are NOT independent.
- **Wrong "failure" probability.** $P(\text{fail}) = 1 - P(\text{pass})$. Not $1 - 2 \times P(\text{pass})$.
- **Drawing only part of the tree.** Some markers require the WHOLE tree drawn even if you only need certain paths. Draw all branches if there is room.

## Quick summary

- **Tree diagram**: branches carry probabilities; paths from root to leaf are full outcomes.
- **Multiply along a path** (AND rule).
- **Add across paths** (OR rule).
- **With replacement** $\Rightarrow$ independent events $\Rightarrow$ stage probabilities don't change.
- **"Exactly one in two stages"** $= 2 \times P(\text{success}) \times P(\text{failure})$.
- **Endpoint probabilities sum to $1$**. Useful sanity check.
